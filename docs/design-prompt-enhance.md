# 即刻对话 · 按住说 = 提示词增强

> 状态：**本期落地**  
> 用户说明书：[`docs/guide-prompt-enhance.md`](guide-prompt-enhance.md) · 官网帮助 lizhenning `other/typenow/help/`  
> 相关：`docs/design-voice-trigger.md` · `docs/design-branding.md` · `docs/design-settings-shortcuts.md`  
> 原则：点按贴口述（可选去水词 / 改错别字，见 `docs/design-voice-trigger.md`）；按住才做提示词增强；对外列为第二能力「与AI对话」，**不另开快捷键或第五技能**；截屏读屏为可选开关（默认关）；不改看屏幕 / 帮我对话主流程；**不自动回车**。

## 目标

在现有「即刻对话」触发键上加一条手势。对外把「与AI对话」列为**第二能力**（产品口号「四个能力，一个助手」；首页指挥台 / 设置快捷键表 / 帮助 / 官网能力详解第二块），仍与即刻对话共用同一键，不另开快捷键或第五技能（截屏读屏为能力开关，默认关）：

| 手势 | 结果 |
|---|---|
| **点按**（按下到抬起 &lt; 400ms） | 开始/结束录音 → 转写 → 可选去水词/改错别字 → **口述**贴进当前输入框（不是提示词增强） |
| **按住**（按下后持续 ≥400ms） | 录音；松手 → 转写 → `rewriteSpokenAsAiPrompt` → 贴增强后的提示词（不发送）。**默认不截屏**；设置 → 能力开关打开「与AI对话时看屏幕」后才静默截屏并读屏 |

给 AI 输入框（ChatGPT、Cursor、邮件草稿等）用：口述意图改写成可直接粘贴的提示词；打开「与AI对话时看屏幕」后才会带上当前屏幕。不是看屏幕问答，也不是帮我对话写回复。

## 手势与冲突

阈值：**400ms**（keydown 起算）。与双击窗口 380ms 错开：短按仍走单击/双击；长按才进增强。

**一旦进入按住**（满 400ms 且键仍按下、未变成组合）：

1. 取消**本会**单击与双击（清掉待触发的单击定时器，`lastAloneTapAt = 0`）
2. 本会抬起不再切换「点按录音」
3. 本会不会触发帮我对话双击

其它约定：

| 场景 | 行为 |
|---|---|
| 按住过程中按下其它键（组合） | 取消本次增强（丢录音与截图），不贴字 |
| 已在点按录音中 | **不进入增强**；本次按下无论长短都只结束点按并贴原话 |
| 看屏幕听音中 | **不进入增强**；点按仍结束提问（现网） |
| 看屏幕其它忙段 / 点按转写中 | 不抢；可重亮忙碌 HUD |
| Esc | 立刻停下（停麦、丢截图、不粘贴），与 `docs/design-esc-cancel.md` 一致 |
| 首页「开始说话」 | 仍走点按开关，不走按住增强 |
| 首页「与AI对话」 | 点按开始增强录音，再点结束（等价按住松手）；HUD 写「再点一次结束」 |
| 硬件 `右 Command+8` / `Win+8` | **仍为点按原话**，不识别按住 |

Mac 语音触发为右 Option / Fn 时：只对该键做按住增强；右 Command 的双击与组合键不变。

Windows：**Alt 点按 = 原话**，**Alt 按住 ≥400ms = 增强**；双击 Alt 仍为帮我对话。`Win+8` 仍点按原话。

## 按住流水线

进入按住后立刻：

1. **开麦录音**：底部 HUD 提示松手后会增强（勿写成「再按一次结束」）  
2. **可选静默截当前窗口**（默认关）：仅当 `enhanceScreenCaptureEnabled` 为 true 时 `captureForEnhance()`（Mac `screencapture -l` 窗口 / 否则按窗口矩形裁），截完即读屏；并按前台 App（Cursor / 豆包 / ChatGPT / WorkBuddy 等）套布局提示，不截整张桌面  

截屏失败不中断录音；未开截屏或无图则只凭口述改写。

松手后：

1. **立刻停麦**（不等截图/读屏）→ 转写（现网 STT 或本机流式）
2. 与点按相同的转写后处理（去水词 / 改错别字，见 `docs/design-voice-trigger.md`）
3. 与读屏抢跑；齐了后 `rewriteSpokenAsAiPrompt`（读屏超时则「无相关上下文」）
4. `pasteIntoFrontApp(text, 'keep-clipboard')`
5. **不按回车 / 不发送**

无声、转写失败、增强失败：HUD 报错，不粘贴。取消（Esc / 组合键）不贴字。

## 增强提示词（模型）

只输出**可粘贴的提示词正文**（给 Cursor / ChatGPT / WorkBuddy 等执行，不是私聊回复，也不是替它作答）。

**核心竞争力（长期）：** 管道只维护一次；好用程度靠 **场景包** 变多变准，不靠第五个技能、不靠把总 prompt 无限加长。

### 技术路线（管道冻结）

```text
按住 → 录音（可选：当前窗口截图即读屏）
松手 → 立刻停麦 → STT（开了看屏幕则 ∥ 读屏收尾，超时=无相关上下文）
              ├─ 场景路由：website | ppt | debug | brief | generic
              ├─ 套对应场景包
              └─ 文字模型写出提示词 → 粘贴（不回车）
```

手势 / STT / 粘贴 **不再为新场景改代码**。新场景 = 新包 + 黄金口试。按 **任务类型** 路由，不按前台 App 名（Cursor / 浏览器标题太脆）。

拿不准走 `generic`（通用扩写），**不得**套建站范例。Debug 与建站同时像时，**debug 优先**。

数据：`src/shared/prompt-scenes/`。官网「与AI对话」四卡与四包 id 对齐：`website` / `ppt` / `debug` / `brief`。

### 首发四包

| id | 官网卡 | 输出骨架 | 允许补全 | 禁止 |
|---|---|---|---|---|
| `website` | 做网站 | 祈使建站 + 页面/模块编号 | 用户点到的功能按模块展开；可补导航、响应式 | 不要写成 HTML 幻灯或纯方案 brief；不要把某次试验口试写成默认模块 |
| `ppt` | 做 PPT | **HTML 分页幻灯**（每页一屏）+ 第 N 页标题与要点 | 合理页数、每页 3～5 点、可翻页 | 禁止 .ppt / .pptx / PowerPoint 文件；不要写成网站 |
| `debug` | 写代码 / 修 Bug | 现象、复现、期望、改动范围 | 把屏幕上的报错/文件写进去 | 不要新开产品/官网需求；不编路径 |
| `brief` | 写方案 / 问 ChatGPT | **目标、约束、输出格式** | 补验收与结构 | 不要写成代码补丁或整站需求 |
| `generic` | （回落） | 祈使任务 + 编号 | 轻度补全 | 不要默认套用建站电商模块 |

### 黄金口试（加包必过）

1. 「做一个公司官网，要有产品介绍和联系我们」→ `website`  
2. 「做十页融资 PPT，市场/产品/团队」→ `ppt`，须有「第 N 页」，且约束为 **HTML 幻灯** 而非 .ppt 文件   
3. 对着红字说「修这个」→ `debug`，含报错原文，不含购物车  
4. 「帮我想周报结构」→ `brief`（目标、约束、输出）  
5. 含糊一句 → `generic`，且不得出现无关的在线购买模块  

### 两步调用（有截图时）

1. **截图理解槽**（轻量）：长边约 1024、JPEG ~70；自配可用更快 VL。官方会员若服务端绑死 32B，仍靠压图 + **15s 超时**降级。只抽事实；无关或超时则「无相关上下文」  
2. **回复槽**：口述 + 摘要 + **当前场景包的 agent 身份** → **线上文字模型**扩写。走独立能力码 `enhance`（与 `reply` 同价），服务端只对它传 `enable_thinking: false`——看屏幕/答题保留思考。`max_tokens` 1200，`finish_reason=length` 按失败处理，不贴半截。失败不本地拼接。  

会员站前置 OpenResty 约 60 秒拿不到正文就回 504 HTML，且该虚拟主机会缓冲 PHP 输出（延迟心跳实测 63 秒仍 504，方案作废）。因此把预算全部压到网关以内：PHP 侧 `CURLOPT_TIMEOUT` 50s 主动放弃并回 JSON，客户端 `enhanceRewrite` / `screenAsk` 均为 55s，收下那个 JSON 错误而不是自己先掐断。真撞上网关时 HUD 明写「网关超时」。

按住时截完图立刻读屏，与说话重叠。松手先停麦，转写与读屏并行，齐了再写提示词。读屏超过约 8 秒 HUD 提示「屏幕有点慢，先按你说的写」。读屏失败/超时只凭口述路由。无图：只走第 2 步。

看屏幕问答 / 答题仍用清晰整屏（长边 1600）和官方 32B 视觉，与增强读屏分开。

官方会员：有图且读屏成功时扣 `reply_vision` + `reply`；读屏降级或无图只扣 `reply`。

### 演进（场景包越加越强）

- **P0（本期）**：路由 + 四包 + 口试  
- **P1**：屏幕上已有上一轮 AI 回复 → 偏 `followup`（补约束，不重开项目）  
- **P2**：翻译/汇总表等新包；每包两条口试；未过口试不准上官网卡  

仍不做：新快捷键、自动发送、按进程名硬编码场景、把总规则写成「如果是 PPT 则…如果是代码则…」长文。与AI对话截屏为可选开关（默认关），不是第五技能。

## 明确不做

- 不另开快捷键或「增强提示词」总开关（语音开着即有按住；首页第二行只是同一手势的展示）  
- 与AI对话截屏读屏默认关，在设置 → 能力开关打开；不是第五技能  
- 不改看屏幕、帮我对话主流程与快捷键  
- 不自动回车  
- 硬件 `Command+8` / `Win+8` 不做按住增强  

## 文案

对外第二能力叫 **与AI对话**（见 `design-branding.md` / i18n `brand.aiTalk.*`）。即刻对话一句话只讲点按贴口述。

HUD 示例：

| 阶段 | zh |
|---|---|
| 首页点按录音 | 再点一次结束，会增强提示词 |
| 按住录音 | 松手后会增强提示词 |
| 转写 | 我记下来了… |
| 读屏（仅打开看屏幕时） | 先看一眼屏幕… |
| 读屏偏慢 | 屏幕有点慢，先按你说的写 |
| 增强 | 正在写成给 AI 的任务说明… |
| 完成 | 增强后的提示词已经填好啦（不发送） |

## 实现要点

- `modifier-tap.ts`：语音键 hold 定时 400ms；忽略 key repeat；进入 hold 后清单击/双击；组合键取消 hold  
- `voice-input.ts`：`beginVoiceHold` / `endVoiceHold` / `toggleVoiceHold`（首页第二行）；点按 `toggleVoiceInput` 原路径不动  
- `llm.ts`：读屏摘要（轻量/超时降级）→ `matchPromptScene` → 按包扩写；模型 `fetch` 有超时  
- `src/shared/prompt-scenes/`：场景包数据与路由  
- 接线：`src/main/index.ts` 的 `modifierTapHandlers`
