# HUD 过程反馈（看屏幕等长流程）

> 状态：落地中（v0.3.6）

## 问题

「看屏幕」链路长（截屏 → 播报 → 听 → 转写 → 想 → 答）。思考阶段若 HUD 不明显，用户会误以为卡死，再按语音键却得到「上一段还在忙」——体验断裂。

## 原则

1. **忙时必见**：凡 `busy` / 长等待，底部 HUD 必须持续可见，不自动消失。  
2. **说人话**：主文案一句口语；可附一行小字说明阶段（如「第 3 步 · 想办法」）。  
3. **动效表意**：看=轻脉冲、听=呼吸圆环、说=波形、想=慢旋轨道、写/转写=转圈。  
4. **冲突时指路**：若语音/帮我对话撞上未结束的看屏幕，不要干瘪报错——**重新亮起当前进度 HUD**，说明在忙什么。

## 看屏幕阶段 → HUD

| 阶段 | 主文案示例 | 动效 |
|---|---|---|
| 截屏 | 正在看屏幕… | look |
| 提示播报 | 我先跟你说一声… | speak |
| 听音 | 我看到屏幕了，你要干什么？… | listen |
| 转写 | 嗯，我听清楚了，记下你的话… | write |
| 思考 | 我看着屏幕想一想…（可能要几秒） | think + 心跳刷新 |
| 回答 | （答案正文） | check |

回答态（`answer`）自动消失见 `docs/design-screen-ask.md`「HUD 长答案」：按时长拉长停留 + 悬停暂停，避免长文正读着被关掉。

## 与其它能力

- 看屏幕非 idle 时：语音 / 帮我对话 **不抢麦、不另起流程**；再次点按只刷新进度提示。  
- 听音中：单击语音修饰键仍 = **结束提问**（原行为保留）。
