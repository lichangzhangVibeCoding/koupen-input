# 模型配置优化设计（对照「闪电说」）

> 状态：**一期已落地；三槽可编辑配置已补齐**（每槽：本地/在线、地址/Key/模型名、保存、测一下）  
> 参考：[闪电说文档 · 入门指南](https://shandianshuo.cn/docs)  
> 原则：先文档后代码；本地套件含语音 + 对话。

---

## 1. 为什么现在会「迷糊」

对照闪电说与我们当前设置页，用户迷路的核心原因不是「字段太少」，而是**心智模型不清晰**：

| 现状问题 | 用户感受 |
|---|---|
| 按「帮你口喷 / 我来口喷」两个功能 Tab 配模型 | 不知道这俩 Tab 和「模型种类」是什么关系 |
| 每个 Tab 里再切「本地 / 在线」 | 和上方「本地模型安装」叠在一起，不知道先点谁 |
| 帮你口喷要同时配文本模型 + 视觉模型 | 不清楚哪个负责看微信截图、哪个负责写回复 |
| 本地只装了 Ollama 聊天/视觉，语音却要另找服务 | 对标软件（闪电说）本地也能语音转写，用户会觉得我们「本地不完整」 |
| 一堆 Base URL / Key / 模型名 | 不知道最少填哪几项就能「跑通」 |
| 缺少「按能力验收」 | 配完不知道有没有真的通 |

闪电说之所以清楚，是因为它把模型配置改成了：

> **先按能力占位（你要跑通哪几件事）→ 再选服务商 → 再填 Key / 选模型 → 每项能单独测通**

而不是「先选功能 Tab，再在功能里塞一堆引擎字段」。

## 2. 闪电说可借鉴的要点

来自其入门文档的关键结构：

### 2.1 能力三件套（模型页的主角）

闪电说要求用户确认三类模型都可用：

1. **语音识别模型**：声音 → 文字  
2. **快速大模型**：转写后的纠错、标点、轻度整理  
3. **高级大模型**：结合屏幕/上下文生成回复、改写、处理任务  

配置完成后，在模型页能一眼看到「三类都已选好」；第三方服务商卡片右上角有**绿色圆点**表示可用。

### 2.2 先跑通模型，再玩别的

文档强调：模型不通，后面语音输入、「帮我说」、技能、记忆都没法稳定验证。  
上手路径是：**模型跑通 → 短按出字 → 长按帮我说**。

### 2.3 自己配模型是一等公民

- 可接火山、阿里云、OpenAI、DeepSeek、硅基流动、Ollama、LM Studio 等  
- 自己配置可长期免费使用产品能力（费用在服务商侧）  
- 会员只是「免配 Key、开箱即用」的捷径，不是唯一路径  

### 2.4 本地语音也是一等能力（已按你的反馈修正）

闪电说 Basic（免费自配）明确包含 **「本地语音模型」**。  
对标里我来口喷可以完全走本地，不是「本地只给大模型、语音必须在线」。

我们的设计改为：

- **本地 = 三件套都可本地**：语音识别 + 截图理解 + 回复生成  
- 对用户统称「本地套件」；内部再分「本地语音模型」与「本地对话模型」（Ollama）  
- 技术上两者引擎不同，但**不能**再对用户说「本地不管语音」

### 2.5 服务商卡片 + 状态灯

用户先理解「我接了哪家服务」，再理解「这家服务给哪个能力用」。  
状态灯回答一个问题：**这条服务现在能不能用**。

## 3. 我们产品对应的「能力槽位」

我们不必照搬闪电说的「快速 / 高级」命名，但要**同样按能力拆槽**。结合 VIP 对话助手现状，建议三槽：

| 能力槽 | 用户一句话理解 | 对应产品动作 | 技术角色 |
|---|---|---|---|
| **A. 语音识别** | 把我说的话变成字 | 右 Command 录音结束 → 转写 | ASR / Whisper 兼容 |
| **B. 截图理解** | 看懂微信聊天窗口 | `Command + 8` 截屏识别联系人与对话 | 视觉多模态模型 |
| **C. 回复生成** | 按人设写出下一条回复 | 识别后生成并粘贴 | 文本大模型 |

说明：

- 闪电说的「快速大模型」（转写后轻度整理）我们**第一期不做独立槽位**，避免再加复杂度；后续若要「转写润色」可再加第 4 槽。  
- 若某服务商一个多模态模型同时胜任 B+C，允许 **B 与 C 选同一个模型**（UI 上提供「与截图理解相同」勾选）。

## 4. 目标信息架构（评审稿）

建议把设置里的「模型相关」收敛成一个独立页面：**模型**（可从侧栏进入，或作为设置首页默认页）。

```text
侧栏
 ├─ 首页
 ├─ 客户
 ├─ 模型          ← 新增主入口（核心）
 └─ 设置          ← 快捷键、权限说明、通用项（弱化模型字段）
```

### 4.1 「模型」页结构（自上而下）

```text
① 跑法三选一（互斥主轴）
   [官方会员] [自配 Key] [本地模型]
   点选即切换；只显示当前方案的配置面板

② 当前方案面板（只出现一个）
   · 官方：登录态 / 积分 / 链到个人中心
   · 自配：一个 Key + 一键套用推荐
   · 本地：一键安装本地套件

③ 能力状态（语音 / 截图 / 回复）
   只读状态灯 + 可选「测一下」——不是第四种配置入口

④ 高级（仅自配展开）
   按槽改地址 / Key / 模型名；一般用户不必碰
```

心智模型：**先选怎么跑 → 三槽自动跟方案走**。不要把「官方 / 自配 / 本地」和「三个坑」做成两套并列选项。

### 4.2 单个服务商配置抽屉 / 子弹

点击服务商卡片后：

1. 预填 Base URL（可改）  
2. API Key（本地保存）  
3. 可选模型列表（常见模型快捷选）+ 自定义模型名  
4. **测连通**：发极短请求，成功则卡片变绿灯  
5. 「用于哪些能力」：勾选 A / B / C（可多选）  
   - 勾选后自动填入对应能力槽，用户仍可改  

**「本地套件」卡片（对齐闪电说本地语音 + 本地大模型）：**

对用户呈现为一张「本地」卡，内部含两个安装单元（技术实现分开，文案合并）：

| 单元 | 能力 | 推荐方案（实现期再定具体包） |
|---|---|---|
| 本地语音模型 | 槽 A | SenseVoice Small / Whisper 等本地 ASR（可一键下载） |
| 本地对话模型 | 槽 B、C | Ollama：视觉 + 文本 |

交互：

- `[一键安装本地套件]`：按序安装语音包 + Ollama 模型（可显示分步进度）  
- 也可只装其中一项  
- 安装完成后，三槽都可切到「本地 xxx」  
- 状态灯：语音就绪 / 对话就绪 分项显示，总灯需两项都可用才全绿（或显示 2/2）

**打包硬依赖（必验，勿跳过）：**

- 本地语音走 `@xenova/transformers`（Whisper）→ 依赖 **`sharp` + 自带 `libvips`（`node_modules/sharp/vendor/**`）**
- 首次安装会从模型仓库拉权重；国内直连 `huggingface.co` 常 `fetch failed`，默认改用镜像 `https://hf-mirror.com/`（可用环境变量 `TALKNOW_HF_ENDPOINT` 覆盖，须带尾斜杠）
- `npm install` 若跳过 scripts，或打包时缺 `vendor`，安装包一点「一键安装」就会报 `libvips-cpp.*.dylib` / sharp 加载失败
- 发版前必须：`node scripts/ensure-sharp.mjs` 通过；`asarUnpack` 含 `**/sharp/**/*` 与 `**/*.{node,dylib}`
- 对话半边（Ollama）与语音半边失败应分项提示：Ollama 成功而语音失败时，不要把整次安装表现成「整包挂掉且堆栈原文」

### 4.3 「设置」页降噪

设置页只保留：

- 帮你口喷快捷键（`Command + 8`）  
- 语音输入开关（右 Command）  
- 上下文条数  
- 权限引导（麦克风 / 屏幕录制 / 辅助功能）  
- 不再把 Base URL、模型名、本地在线大杂烩堆在这里

## 5. 关键交互规则

### 5.1 先问「能力通不通」，再问「用哪家」

用户打开模型页，第一眼应看到三槽状态，而不是一排表单。

### 5.2 每槽必有「测一下」

| 槽位 | 测试方式（建议） |
|---|---|
| A 语音识别 | 录音 2 秒或上传一小段测试音频 → 返回文字 |
| B 截图理解 | 用一张内置示例聊天截图 → 返回 JSON/联系人名 |
| C 回复生成 | 固定提示「只回复 ok」→ 成功即通 |

全部绿灯后，顶部显示「模型已跑通，可以去首页试用」。

### 5.3 本地 / 在线不再做成功能 Tab 主轴

改为：

- **服务商维度**区分本地套件与在线（硅基、OpenAI…）  
- **能力槽**只关心「当前绑的是谁」  
- 用户切换某槽的服务商即可，不必先理解「帮你口喷 Tab 的本地开关」  
- **本地语音与本地对话并列**：都叫本地，不暗示「只有聊天能本地」

### 5.4 默认推荐路径（降低决策）

**出厂默认：官方会员。** 新用户先注册/登录，三槽走服务端官方优化模型（免填 Key，按次扣积分）。自配与本地仍是一等公民，在模型页可随时改。

首次进入模型页，官方卡为「使用中」；未登录时主按钮去个人中心。另外两条可一键切换：

1. **自配 Key（硅基流动推荐）**  
   - A：`FunAudioLLM/SenseVoiceSmall`  
   - B：常用 VL 模型  
   - C：常用文本模型  
   - 用户只需填一个 Key  

2. **本地推荐（本地套件）**  
   - A：本地语音模型（SenseVoice / Whisper，一键下载）  
   - B：Ollama 视觉小模型  
   - C：Ollama 文本小模型  
   - 用户点「一键安装本地套件」，无需 Key  

可混搭：例如 A 用本地语音，B/C 用硅基在线——三槽独立选择即可。

### 5.5 文案用「人话」

少写：Base URL、inferenceMode、OpenAI 兼容。  
多写：

- 「看聊天截图用哪个模型」  
- 「写回复用哪个模型」  
- 「听语音用哪个模型」  
- 「服务是否可用（绿灯）」  

高级字段（Base URL）折叠进「高级选项」。

## 6. 与现状功能的映射（迁移策略）

| 现有配置 | 迁移到 |
|---|---|
| 语音 Tab · 在线 STT | 能力槽 A + 硅基/OpenAI 服务商 |
| 语音 Tab · 本地 STT | 本地套件 · 本地语音模型 → 槽 A（一期做一键安装，不再只丢一个空 URL） |
| 帮你口喷 · 视觉模型 | 能力槽 B |
| 帮你口喷 · 文本模型 | 能力槽 C |
| Ollama 安装区 | 并入「本地套件」卡片（对话单元） |
| 功能 Tab 本地/在线开关 | 删除为主轴；由各槽所选服务商决定 |
| 设置里的快捷键等 | 留在「设置」页 |

数据层可保留现有字段，仅改读取逻辑：`stt*` → 槽 A，`vision*` → 槽 B，`modelName` → 槽 C。评审通过后再做字段整理。

## 8. 分期落地建议

### 一期（解决迷糊 + 对齐本地语音，优先做）

1. 新增「模型」页：三能力槽 + 服务商卡片 + 状态灯  
2. 每槽「测一下」  
3. **在线**：硅基推荐一键套用  
4. **本地套件**：一键安装「本地语音模型 + Ollama 对话模型」，三槽都可切本地（对齐闪电说）  
5. 设置页去掉模型大表单，只留快捷键/权限  
6. 文案全面改成人话  

### 二期（体验增强）

1. 服务商模型下拉（按厂商拉常用列表，可手填）  
2. B/C「使用同一模型」快捷勾选  
3. 顶部 onboarding 三步：模型跑通 → 试语音 → 试 Command+8  
4. 本地语音模型体积/精度可选（Small / 更大）  

### 三期（会员免配 Key · 已开设计）

1. 转写后「轻度整理」独立快速模型槽（对齐闪电说）  
2. **会员式「免配 Key」**：统一积分 + 薄代理转发第三方（先硅基流动），见 `docs/design-membership.md`

## 9. 成功标准（验收）

用户第一次打开「模型」页，在 **3 分钟内**能完成：

1. 看懂三件事分别是干什么的  
2. 用「硅基推荐」或「本地套件」配好至少一条完整链路（含语音）  
3. A/B/C 三槽都能测出绿灯（本地或在线均可）  
4. 回到首页，不需要再猜该填哪个 URL  

主观标准：用户不再问「我到底该配哪个模型」；也不会觉得「对标能本地语音、我们本地却不能」。

## 10. 明确不做（本设计范围外）

- 会员体系见 `docs/design-membership.md`（本文件只保留三槽配置；额度/支付不在此展开）  

- 一期不做「快速大模型」润色槽  
- 不改帮你口喷/语音的主流程逻辑，只改配置体验、绑定方式，以及本地语音安装能力

## 11. 请你拍板的问题（已按你的反馈修正）

1. **是否同意**独立「模型」页 + A/B/C 三槽？  
2. **在线默认**是否用「硅基一键推荐」？  
3. **本地默认**是否用「本地套件一键安装」（语音本地 + 对话本地），与闪电说一致？  
4. **截图理解与回复生成**是否允许默认绑同一个多模态模型（减少一次选择）？  

> 原「Ollama 不管语音」方案已撤回：本地语音改为一期必做，与对话本地同属「本地套件」。

你确认后，再按「一期」开工改代码。
