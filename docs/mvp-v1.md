# 即刻对话 — MVP v1 功能与设计文档

> 状态：**可运行（v0.4.0 墨色信号 VI）**  
> 平台：macOS 优先（Windows 可打包）  
> 品牌 / VI：`docs/design-branding.md` · `docs/design-vi-ink-signal.md`  
> 目标：本机对话助手——语音填字 / 截图回复 / 看屏幕问答 → 建档与记忆 → 文字由用户确认后发送

---

## 1. 产品定位

**即刻对话**：本机对话助手，少打字、快回人。（曾用名：口喷输入）

通用桌面工具（不面向单一行业），核心是：

- 按「人」建档（联系人）
- 按「人」记人设与画像
- 按「人」攒对话记忆
- 在真实聊天窗口上填入文字（不自动发送）
- 看整屏回答问题（看屏幕）

三大对外能力（名 + 一句话必须成对出现）：

| 对外名 | 一句话 |
|---|---|
| **即刻对话**（语音） | 点按：原话贴进输入框；按住：按屏幕增强成提示词再贴入（不发送） |
| **帮我对话** | 看当前聊天截图，按人设生成回复并填入（不发送） |
| **看屏幕** | 我看着整屏，你说要干什么，我按你说的办 |

---

## 2. 目标用户与场景

| 项目 | 说明 |
|---|---|
| 用户 | 需要维护多段私聊、希望少打字的人 |
| 对象 | 微信/QQ 等私聊中的重要联系人 |
| 帮我对话 | 打开聊天窗口 → 默认双击**右 Command**（或 `右 Command+0`）→ 识别归档并生成回复 → 粘贴到输入框 → 用户确认后发送 |
| 即刻对话 | 点按触发键开始口述 → 再按结束 → **原话**贴入（Mac 默认**右 Command**，可改为右 Option / Fn；或 `右 Command+8`）。按住 ≥400ms 松手 → 按整屏增强提示词后贴入（不发送），见 `docs/design-prompt-enhance.md` |
| 看屏幕 | `右 Command+Shift+1` 截整屏 → 口述问题 → 再按结束 → HUD + 剪贴板回答 |

---

## 3. 平台策略

| 版本 | 策略 |
|---|---|
| MVP v1 | **macOS 安装版优先**（`.dmg` / `.app`） |
| 后续 | 同一套代码打 Windows 安装包，不做原生双端重写 |

**技术选型原则**：选跨平台桌面框架（建议 Electron 或 Tauri），业务逻辑与数据层和 UI 解耦，避免 Mac 做完再「复制一套」Windows。

## 4. MVP v1 功能清单

### 4.1 模型与设置（当前实现）

模型配置见独立「模型」页与 `docs/design-model-config.md`。设置页保留快捷键、开关、配置导出。

| 能力 | 对外名 | 默认触发 |
|---|---|---|
| 语音 → 文字 | **即刻对话** | Mac：右 Command（默认）/ 右 Option / Fn **点按贴原话、按住增强**；硬件 `右 Command+8` 仅点按原话。Win：Alt 点按原话 / 按住增强；`Win+8` 仅点按原话 |
| 截屏 → 回复 | **帮我对话** | 双击右 Command / `右 Command+0` |
| 看屏幕问答 | **看屏幕** | `右 Command+Shift+1`（Win：`Win+Shift+1`） |
| 看屏幕答题 | **看屏幕答题** | `右 Command+Shift+2`（Win：`Win+Shift+2`）：截屏后直接给正确答案 |

**设计原则：**

- 对外名旁必须有一句话解释（见 `design-branding.md`）
- 本地用于试用；在线用于效果升级
- Key 仅存本地

---

### 4.2 帮你口喷（全局快捷键）

- 提供**低冲突默认快捷键**：`Command + 8`（Mac；避开豆包等常用的 Option + Space）
- 用户可在设置中修改（界面只展示 Mac 键名）
- 快捷键触发后进入主流程：截屏当前活跃窗口 → 识别 → 归档 → 生成回复 → 自动粘贴到输入框

---

### 4.2.1 我来口喷（我来口喷）

面向长段口述输入（私聊、备注、人设等任意当前输入框）。

**默认操作（Mac）：**

- 点按右 Command 一次 → **开始录音**；再点按一次 → **结束并贴原话**
- **按住**右 Command ≥400ms → 静默整屏截图 + 录音；松手 → 按屏幕增强提示词后贴入（不发送）。见 `docs/design-prompt-enhance.md`
- 若按住的同时按了其他键（如 Command + C），则视为正常组合键，**不触发**录音 / 增强

**结束后自动：**

1. 将语音转成文字（支持较长音频）
2. **自动粘贴到当前焦点输入框**（不按发送）
3. **同时保留在剪贴板**，便于再贴一次

**状态提示（底部 HUD）：**

| 阶段 | 文案示例 |
|---|---|
| 录音中 | 正在录音…再按右 Command 结束 |
| 转写中 | 正在转成文字… |
| 完成 | 已填入输入框，并已复制到剪贴板 |
| 失败 | 转写失败（简短原因） |

**转写引擎：**

- **在线**：OpenAI / 硅基流动等 Whisper 兼容接口（如 `whisper-1`、`FunAudioLLM/SenseVoiceSmall`）
- **本地**：本机 Whisper 兼容转写服务（可配置 Base URL / 模型名）
- 需授予：**麦克风**、**辅助功能**（粘贴）

---

### 4.3 桌面底部状态提示（HUD）

快捷键触发后，在**桌面下方适当位置**显示轻量状态条（不抢焦点、不挡住聊天输入区为佳）：

| 阶段 | 提示文案（示例） |
|---|---|
| 识别中 | 正在识别… |
| 生成中 | 正在生成回复… |
| 录音中 | 正在录音…再按右 Command 结束 |
| 转写中 | 正在转成文字… |
| 粘贴完成 | 已填入输入框，确认后发送 |
| 失败 | 识别失败 / 生成失败（简短原因） |

**设计原则：**

- 状态条悬浮在屏幕底部居中或偏下安全区，处理结束后自动消失（或短暂停留后消失）
- 不强制弹出大型工作台打断当前聊天；主流程尽量「无感完成」
- 设置页、联系人档案等仍走独立窗口，不依赖此 HUD

---

### 4.4 截屏识别与客户建档

**触发后流程：**

1. 截取当前**活跃窗口**（不是全桌面）
2. 识别聊天客户端类型（MVP 先做：**微信**；QQ 架构预留，能识别则归档到对应分类）
3. 从界面中识别：
   - **左侧/会话信息**：当前联系人名称
   - **右侧/聊天区**：当前可见文字消息
4. 按「渠道 + 联系人」建档或匹配已有档案  
   例：`微信 / 李厂长`
5. 将本次识别到的文字消息入库，并区分发言方：
   - **对方说的**
   - **我说的**

**MVP 明确不做：**

- 图片消息识别与存储
- 语音、表情包、红包、视频号等富媒体
- **自动点击发送按钮**（见 4.7）

---

### 4.5 按人维度的人设与联系人详情页

每个联系人独立维护一套「我对 TA 扮演的人设」，并在**联系人详情页**深度管理。

#### 页面结构（自上而下）

1. **顶部：我对 TA 的人设配置区（独立区块）**
   - 人设名称、人设描述、人设标签
   - 编辑后自动保存（实时落库）
   - 支持根据历史聊天一键建议/刷新人设要点与标签（可再手工改）

2. **顶部下方：客户人物画像区（独立区块）**
   - 画像总结（对方是谁、习惯、偏好、雷点等）
   - 关键信息标签（可随时新增 / 删除）
   - 关键事实记录（随手记：日期、事实正文）
   - 同样支持根据历史聊天生成/更新画像与标签

3. **下方：聊天历史（仿微信会话 UI，纵向铺开）**
   - 气泡左右区分：对方左、我右
   - 保留每条消息的真实时间；超时距插入时间分割条（微信风格）
   - 支持按**日期时间段**筛选
   - 背景与气泡样式尽量还原微信聊天记录观感

**人设 / 画像字段：**

- 人设名称、人设描述、人设标签
- 客户渠道、显示名
- 联系人标签、画像总结、关键事实列表
- 备注（可选）

**原则：**

- 10 个客户 = 10 套人设，互不串用
- 生成回复时，只注入**当前联系人**的人设 + 画像摘要，不注入其他人的

---

### 4.6 对话记忆与上下文

#### 存储（完整记忆）

本地数据库保存该客户的全量文字消息：

- 渠道（微信/QQ…）
- 联系人 ID/名称
- 发言方（我 / 对方）
- 文本内容
- 时间戳
- 来源（本次截屏识别批次）

#### 给模型用的上下文（省 token、不断档）

MVP 采用两层（第三层可二期）：

| 层 | 内容 | 用途 |
|---|---|---|
| A. 人设卡 | 当前联系人的人设 + 标签 | 每次必带 |
| B. 近期窗口 | 最近 N 条原文（建议默认 30～50 条，可配置） | 保证刚聊的内容不丢 |
| C. 长期摘要（二期） | 更早对话压缩成要点 | 聊很久以后再上，MVP 可先不做 |

**原理：**

- **完整库**：给人看、给以后检索，不每次全塞模型
- **窗口 +（后期）摘要**：控制 token，又保留「我俩聊过什么」的连续性
- 第三天再聊时：至少带上人设 + 库里最近窗口；若窗口盖不住更早关键事实，二期用摘要补

---

### 4.7 回复生成与自动粘贴（不发送）

根据：

1. 当前联系人人设  
2. 历史对话上下文  
3. 本次截屏识别到的最新对话  

**去除 AI 味儿（可开关，默认开）：** 设置项 `deAiToneEnabled`。开启时在生成 prompt 中强化「像真人微信私聊」约束（短句、口语、少排比/总结腔、禁止客服话术与「作为 AI」类表达）；关闭则只用基础自然语气要求。

生成回复文本后：

1. **自动将回复粘贴/填入当前聊天窗口的输入框**
2. **不点击发送按钮**，由主播过目后自行发送
3. 底部状态条提示「已填入输入框，确认后发送」

**边界：**

| 做 | 不做 |
|---|---|
| 自动填入输入框 | 自动点发送 |
| 用户可改字再发 | 静默发出去 |

**失败兜底：**

- 若自动粘贴失败（焦点不在输入框、权限不足等）：底部提示失败，并提供「复制到剪贴板」备用
- 设置页 / 联系人详情仍可查看历史与人设；识别纠错能力可在联系人详情或简易复核入口完成（不阻断主路径）

## 5. 端到端使用流程（MVP）

```text
[用户在微信与某人聊天]
        │
        ▼
[按下全局快捷键]
        │
        ▼
[屏幕下方显示：正在识别…]
        │
        ▼
[截取当前活跃窗口]
        │
        ▼
[OCR/版面识别：联系人名 + 聊天文字 + 发言方]
        │
        ▼
[匹配或新建联系人档案（渠道 + 姓名）]
        │
        ▼
[新消息去重后写入本地对话库]
        │
        ▼
[状态更新：正在生成回复…]
        │
        ▼
[读取：人设 + 最近 N 条历史 → 调用大模型]
        │
        ▼
[将回复自动粘贴到当前聊天输入框]
        │
        ▼
[状态提示：已填入输入框，确认后发送]
        │
        ▼
[用户确认 / 小改 → 自行点发送]
```

**配套界面（MVP）：**

1. 模型配置  
2. 快捷键设置  
3. 联系人列表 / 联系人详情（人设编辑 + 历史对话浏览）  
4. 桌面底部状态 HUD（识别中 / 生成中 / 已填入 / 失败）  
5. 粘贴失败时的剪贴板备用能力

## 7. 关键设计原理

### 7.1 为什么用「截屏识别」而不是官方 API

微信/QQ 对第三方读取聊天记录限制很严。MVP 用「用户主动快捷键 + 当前窗口截屏 + 识别」：

- 不需要破解或注入客户端  
- 用户可控、每次主动触发  
- 代价是识别准确率依赖 UI 与 OCR；联系人档案页保留纠错与人设编辑能力  

### 7.2 为什么必须「发言方」分开存

模型要学的是「我怎么回他」，不是糊成一段独白。角色不清会导致：

- 把对方的话当成自己说的  
- 人设语气漂移  
- 历史摘要失真  

### 7.3 为什么人设按人隔离

对不同联系人的人设、边界、亲密度不同。全局人设会串戏，重要联系人场景尤其危险。

### 7.4 为什么「自动粘贴，但不自动发送」

- **自动粘贴**：减少手动复制步骤，使用节奏更快，符合私聊场景  
- **不自动发送**：最后一道人审，避免识别错人或回复不当直接发出去  

即：

**机器负责又快又像 → 人负责最后确认发出**

### 7.5 为什么用底部轻量状态条

主流程不应打断当前聊天窗口焦点（粘贴需要输入框仍可用）。底部 HUD 只反馈进度，不抢操作。

## 8. MVP 明确不做（Out of Scope）

- 图片/语音/视频消息理解  
- 多开账号复杂管理（可后做）  
- 云端同步、多设备账号系统  
- **自动点击发送**（已填入输入框即可）  
- 公会多人协作后台  
- 礼物榜单自动同步、直播间数据采集  
- 完美的 QQ 适配（架构预留即可）  
- 长期摘要记忆（二期增强）

## 9. 风险与对策（开发前对齐）

| 风险 | 影响 | MVP 对策 |
|---|---|---|
| 微信 UI 识别不准（名字/气泡左右） | 建错档、角色反了 | 联系人详情可改名/看历史；必要时支持合并档案 |
| 重复截屏导致消息重复入库 | 历史噪声 | 文本 hash + 近邻去重 |
| OCR 对昵称特殊字符不稳 | 同一人多个档案 | 联系人列表支持合并/手动改名 |
| 模型 Key 配错 | 无法回复 | 配置页提供「测试连接」 |
| 上下文过长 | 贵、慢 | 仅注入最近 N 条 + 人设 |
| 自动粘贴失败（焦点/辅助功能权限） | 回复进不了输入框 | 提示授权；失败则写入剪贴板并 HUD 告知 |
| 粘贴时焦点不在输入框 | 贴错位置 | 尽量先激活原聊天窗口输入区；失败走剪贴板兜底 |

## 11. MVP 完成标准（验收）

满足以下即视为 v1 可交付：

1. Mac 上可安装、可启动  
2. 能配置至少一种国内或海外模型并测试通过  
3. 全局快捷键能唤起  
3b. 右 Command 点按可开始/结束长文本语音转写，结果粘贴到输入框并保留在剪贴板  
4. 触发后屏幕下方出现「正在识别…」等状态反馈  
5. 在微信聊天窗口触发后，能识别出联系人名称与可见文字  
6. 消息按「我/对方」入库，同一联系人可累积多日记录  
7. 可为客户编辑独立人设  
8. 能基于人设 + 最近历史生成回复，并**自动粘贴到聊天输入框**  
9. **不自动点发送**；粘贴失败时有剪贴板兜底  
10. 不处理图片

## 12. 技术实现建议（供开发启动用）

| 层 | 建议 |
|---|---|
| 桌面壳 | Electron（生态成熟，全局快捷键/截屏资料多）或 Tauri（更轻） |
| 本地存储 | SQLite |
| 识别 | 窗口截屏 + OCR（macOS 可评估系统 OCR / 本地 OCR 库）+ 简单版面规则（左名右聊） |
| 模型调用 | OpenAI 兼容 HTTP API，便于国内中转与海外端点统一 |
| 自动粘贴 | macOS 辅助功能权限 + 激活原窗口输入框后模拟粘贴（或 Accessibility 写入）；失败则写剪贴板 |
| 底部 HUD | 无边框置顶小窗，不抢键盘焦点（`focusable: false` 一类策略） |
| 安全 | API Key 存系统钥匙串或本地加密存储 |
